# 数据库延迟升高与查询异常

## 适用场景

当业务服务出现请求超时、HTTP 502、接口延迟升高或数据库相关错误时，可以参考本文排查数据库是否是故障原因。

本文是通用排查指南，不代表当前事故一定由数据库引起。

## 典型表现

- 数据库查询延迟升高，尤其是 P95、P99 等高分位延迟。
- 数据库连接建立失败、连接获取超时或连接池等待增加。
- 慢查询、锁等待、死锁或事务执行时间明显增加。
- 数据库 CPU、I/O、活动连接数等资源指标异常。
- 上游业务请求超时与数据库异常在时间上存在关联。

## 调查步骤

1. 检查数据库连接状态、活动连接数、连接等待和连接获取错误。
2. 检查查询延迟、慢查询、锁等待和事务异常。
3. 对比数据库指标和业务服务延迟、错误率的变化时间。
4. 检查连接池配置、连接泄漏以及数据库连接是否被长事务占用。
5. 如果数据库指标正常，继续检查下游依赖、网络、线程池、请求队列及其他资源瓶颈。

## 区分数据库故障与连接池故障

连接池耗尽不一定意味着数据库本身异常。

如果连接池等待显著增加，但数据库查询延迟和数据库资源使用率正常，需要进一步调查连接泄漏、连接未释放、连接池容量不足或并发请求激增。

如果数据库查询延迟、锁等待或资源使用率同时异常，才有更充分的理由进一步怀疑数据库内部问题。

## 判断原则

- 数据库延迟升高与业务超时同时发生，只能说明二者存在关联。
- 必须结合时间顺序、请求链路和实际观测判断因果关系。
- 如果没有数据库专项观测，不能仅凭业务日志确认数据库根因。
- 如果数据库指标正常，应保留并调查其他候选原因，而不是强行确认数据库故障。
